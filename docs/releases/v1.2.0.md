# KMonad Device Manager v1.2.0

KMonad Device Manager 1.2.0 adds the read-only keyboard input-scanning contract
while preserving independent per-keyboard supervision.

## Highlights

- **Input capability scans:** `device.inputscan.get` reports a deterministic,
  versioned `kmonad-v1` token set, digest, unmapped-key count, and evidence
  generation for a connected keyboard.
- **Bounded key probes:** `device.inputscan.probe` and the equivalent CLI
  commands wait for one named keypress without changing mappings; unrelated
  keyboards continue running.
- **Contract coverage:** JSON Lines fixtures, replay tests, and an opt-in
  real-device TEST-04 acceptance run cover board agreement, identification,
  ISO/ANSI probing, and hotplug invalidation.
- **Vocabulary correctness:** keypad Enter now emits the valid KMonad token
  `kpenter` rather than the invalid `kpen` spelling.

## Upgrade notes

- Clients must normalize catalog spellings through KMonad keycode identity;
  `kmonad-v1` intentionally emits canonical manager spellings such as
  `102nd`, `kpenter`, `numlock`, `scrolllock`, `sysrq`, and `compose`.
- The real-device TEST-04 run is opt-in and requires a running manager and a
  physical keyboard; it is not part of CI.

## Verification and installation

Linux `amd64` and `arm64` archives include SHA-256 checksums, SPDX SBOMs, and
GitHub build provenance attestations. Verify a download with:

```sh
sha256sum -c SHA256SUMS
gh attestation verify <archive> --owner lukelex
```

Install the extracted archive with its included `install.sh`, or use the Arch
package. See `kmonad-device-manager --help --json` and the Wiki API contract
for complete CLI and same-user API details.
