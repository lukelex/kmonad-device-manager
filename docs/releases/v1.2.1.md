# KMonad Device Manager v1.2.1

KMonad Device Manager 1.2.1 fixes public-state revision tracking so clients can
reliably detect changes between reads and configuration validation previews.

## Highlights

- **Stable idle revisions:** `state_revision` advances only when a public state
  transition event is published. Unchanged reconciliation, poll ticks, and
  read-only requests no longer advance it.
- **Complete configuration notifications:** configuration name and external
  content-revision changes now publish configuration events.
- **Accurate handshake revision:** `session.hello` returns the current public
  revision instead of a hard-coded zero.
- **Stronger coverage gate:** CI and release verification now require at least
  65% Go statement coverage.

## Upgrade notes

Equal revisions from the same `server_id` mean no public state transition was
published between the reads. Health counters and progress timestamps may still
change without advancing the revision. A refresh that discovers a real external
change continues to publish events and advance the revision.

Clients should continue using `server_id` to detect manager restarts and obtain
a fresh snapshot when resynchronization is required.

## Verification and installation

Linux `amd64` and `arm64` archives include SHA-256 checksums, an SPDX SBOM, and
GitHub build provenance attestations. Verify a download with:

```sh
sha256sum -c SHA256SUMS
gh attestation verify <archive> --owner lukelex
```

Install the extracted archive with its included `install.sh`, or use the Arch
package. See `kmonad-device-manager --help --json` and the Wiki API contract
for complete CLI and same-user API details.
